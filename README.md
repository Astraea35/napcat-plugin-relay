# napcat-plugin-relay

NapCat 私聊与群聊 @ 中转、引用回复、好友审批、定时消息和群名片保护插件。无第三方运行依赖。

## 功能

- **消息中转**：默认只转发私聊和群聊中明确 @ 机器人的消息，忽略自身消息，避免循环。支持文字、图片、文件等消息。
- **引用回复**：管理员在机器人私聊中引用中转消息回复，消息回到原私聊或原群；可同时引用对方最初的消息。只有配置的管理员私聊能执行管理指令和引用回复。
- **免打扰**：识别 QQ NT 群提醒状态、私聊屏蔽与好友消息通知设置，并支持手动免打扰名单。QQ NT 接口随版本变化，无法读取状态的会话可加入手动名单。
- **好友申请**：关闭自动同意时，发送申请通知，管理员引用回复「同意」「同意 备注名」或「拒绝」进行审批。开启自动同意或匹配自动同意关键词时，**静默通过，不发送申请通知或通过通知**；失败只记录日志。重复申请事件会去重，已处理的通知不能再次审批。
- **群定时消息**：支持文本、图片、内置动图，以及时间点前后的随机浮动；关闭「发送图片」即可发送纯文本。
- **群名片保护**：只检查机器人自己的名片，限定在配置群和单独设定了名片的群；检测到被修改或清空后，通知管理员并延迟改回，成功或失败再通知。保留默认 10 分钟延迟，可配置。通知事件与每 2 分钟轮询互相补充，关闭定时群发不影响名片检测。

## 定时发送与防刷屏规则

1. 始终使用 **Asia/Shanghai 北京时间**，每群每天最多发一条；自动发送、活跃补发、单群手动发送均遵守每日上限和 08:00 时间限制。
2. 08:00 前不发送。随机时间取设定窗口与当天 `08:00:00—23:59:59` 的交集；窗口全部早于 08:00 时顺延到 08:00，不跨日随机。
3. 首次发送后，群内**其他成员**的消息数必须严格 **大于 n** 才允许下一次发送。例如 n=15 时，15 条仍等待，第 16 条才达标；n=0 时需有至少一条新消息。
4. 到时间仍不达标则等待，计数跨天累计，不因换天清零；达标且当天时间点已到后补发。一周没聊天也不会连续发七条，恢复活跃后最多发当天的一条。
5. 重复事件、自身消息和上次发送前的旧消息不增加活跃计数。每日发送记录、等待状态和当天随机计划会持久化，重载不会随意重新抽时间。
6. 发送前先保存当日占位，防止并发重复发送；如果接口超时、结果不确定或进程在发送中断开，当天不自动重试，避免重复。磁盘无法保存占位时停止发送。关闭活跃检测仍保留每日上限与 08:00 限制。
7. 刚启动时已经错过且未保存计划的旧时段会跳过；已有等待任务可以继续等待并在达标后发送。

## 安装

将发布包解压到 **NapCat 实际插件目录**下的 `napcat-plugin-relay` 文件夹，目录内应直接包含 `package.json`、`index.mjs` 和 `assets/`。配置和运行数据由 NapCat 放到独立的 `config/plugins/napcat-plugin-relay/`，不要把数据目录当成插件安装目录。

在 NapCat WebUI 的「插件管理」启用「消息中转传话」，配置目标管理员 QQ。**不要照搬他人的账号、群号或名片配置。**

部分 NapCat 版本仅加载其官方插件白名单，且禁用了本地 ZIP 导入。这些版本会拒绝本插件，即使文件已安装也不会显示为正常运行；需要由实例管理员决定如何允许自定义插件。插件本身不会修改 NapCat 内核或其他插件。

## 配置

在 NapCat WebUI 插件配置界面保存，配置立即生效。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `target_qq` | 空 | 接收消息的管理员 QQ，需自行填写 |
| `forward_private` | `true` | 转发私聊 |
| `notify_on_at` | `true` | 转发群聊明确 @ 机器人的消息 |
| `forward_group` | `false` | 转发普通群聊；默认关闭 |
| `forward_group_at_only` | `true` | 群转发仅限 @ 机器人 |
| `ignore_dnd` | `true` | 读取 QQ NT 免打扰与屏蔽设置 |
| `dnd_list_str` | 空 | 手动排除的 QQ/群号，逗号或空白分隔 |
| `enable_quote_reply` | `true` | 回传时引用原始消息 |
| `forward_file` | `true` | 转发文件卡片，引用说明或可取得消息 ID 的文件卡片均可回复 |
| `send_confirmation` | `true` | 回复成功后向管理员发送回执 |
| `show_sender_info` | `true` | 中转消息添加来源信息 |
| `show_original_nickname` | `false` | 好友备注后是否附带原昵称 |
| `forward_friend_request` | `true` | 手动审批模式下发送申请通知 |
| `auto_approve_friend` | `false` | 静默自动同意，开启后不发申请通知 |
| `auto_approve_keyword` | 空 | 验证消息包含关键词时静默同意 |
| `enable_schedule` | `true` | 启用群定时消息；未配置群号则不发送 |
| `schedule_groups` | 空 | 目标群号，逗号或空白分隔 |
| `schedule_times` | `12:30` | 北京时间 HH:mm，可配置多个时间点，仍每天最多一条 |
| `schedule_random_minutes` | `0` | 时间点前后随机浮动分钟数，0 为准点，最大 1440 |
| `schedule_text` | 空 | 定时发送的文本 |
| `schedule_send_image` | `true` | 是否同时发送图片；关闭后需填写文本 |
| `schedule_custom_image` | 空 | 图片路径、URL 或 base64；留空使用内置动图 |
| `enable_schedule_activity_check` | `true` | 启用跨天活跃检测 |
| `schedule_min_other_msgs` | `5` | 阈值 n；必须有 **> n** 条其他成员消息 |
| `auto_protect_group_card` | `true` | 检测并恢复受保护群的机器人名片 |
| `default_group_card` | 空 | 默认期望名片；为空时初次记录当前非空名片 |
| `protect_card_delay_minutes` | `10` | 检测变化后多久改回，范围 1—1440 分钟 |

## 常用指令

仅在配置的管理员与机器人私聊中使用；`<群号>` 等占位符需替换。

```text
#中转状态
#设置群聊 <群号1>,<群号2>
#设置时间 12:30
#设置随机 60
#设置发言门槛 15
#开启月薪喵
#关闭月薪喵
#添加免打扰 <QQ号或群号>
#删除免打扰 <QQ号或群号>
#同意 <QQ号> [备注名]
#拒绝 <QQ号>
#群名片
#设置群名片 <群号> <期望名片>
#设置改名延迟 10
#立即改名片 <群号>
#取消改名片 <群号>
```

`#测试月薪喵 [群号]` 会真实发送，并遵守每日上限、08:00 限制和活跃检测；未配置群号时只向管理员私聊展示图片预览。

## 数据与隐私

`config.json`、`message_map.json`、`protected_group_cards.json`、`group_schedule_activity.json`、`daily_schedule_plan.json` 均为本地私有数据，已加入 `.gitignore`，不进入发布 ZIP。引用映射包含聊天来源和好友申请标识，应与凭据一样保管，备份时也不要公开。

公开默认管理员、目标群和名片均为空。仓库仅发布源码、说明、测试、许可证与内置图片，不提供任何真实账号配置。

## 验证

需要支持 `node:test` MockTimers 的 Node.js 版本；测试在 Node.js 24 验证。

```bash
npm run check
npm test
```

测试使用模拟时钟、临时目录和模拟 OneBot Action，不向真实 QQ 或群聊发送消息。覆盖引用回传、免打扰、好友审批、静默自动同意、跨天等待、严格阈值、并发与每日限额、重载持久化、随机时间范围、名片保护和配置校验。QQ 客户端实际事件与原生免打扰接口仍需在已获准加载插件的实例中验证。
